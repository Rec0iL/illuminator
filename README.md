# Illuminator

**English** · [Deutsch](README.de.md)

Turns a rulebook or document (Markdown, Word, PDF or plain text) into an illustrated PDF that looks like a printed book: cover, chapter banners, one image per section, two-column layout, running heads and page numbers. The images are generated by AI to match each section.

```
Text ──► prompts (agy | Claude) ──► images (agy | Gemini API | ComfyUI) ──► PDF (WeasyPrint)
```

The image prompts are written by **agy** (Antigravity CLI) or, alternatively, by the **Claude Code CLI** (`claude`; set under Engine → Prompt generator, or `"llm": "claude"` in `project.json`). The CLI only receives text and returns JSON; it runs in an empty temp folder without file or shell permissions. The images themselves are generated by agy by default (built-in image tool, no API key needed), or by the Gemini API or a local ComfyUI, see "Image engines".

## Requirements

- Python 3.10+ with `pip install -r requirements.txt` (PySide6, markdown, WeasyPrint, Pillow; `google-genai` only for the Gemini API engine)
- Fetch the fonts once (not part of the repo): `python3 fetch_fonts.py` (Google Fonts, SIL OFL)
- [agy](https://antigravity.google) on your `PATH` and logged in (used for prompts and the default image engine); alternatively the [Claude Code CLI](https://claude.com/claude-code) (`claude`) for the prompts
- ComfyUI engine only: ComfyUI (e.g. via Pinokio) with an image model, default `http://127.0.0.1:8188`
- For PDF import: `pdftotext` (poppler-utils)

## Start

```bash
python3 illuminator.py gui
```

Without an argument the GUI opens the last used project. **Recent projects** (next to "New project…") lists the ten most recent ones.

Images in the Markdown with a relative path (e.g. `docs/screenshots/x.png`) are looked up next to the source file first, then in the project's `bilder/` folder and the project folder itself, with the path and with the bare file name. Missing images are reported by the build as "WARNUNG: Bild nicht gefunden".

## Workflow in the GUI

1. **New project…**: pick a rulebook (`.md`, `.docx`, `.pdf`, `.txt`) and an empty project folder. Word files are converted locally from their heading styles; PDF and text are converted section by section by the LLM (wording is preserved). Heading levels are then aligned with the original: chapters are the first-level entries of the table of contents; parts before the first such chapter that are set in the largest font also become chapters. Below that, heading font sizes determine the levels, and a subtitle on the same line is merged into its heading. The table of contents itself is not kept in the text. For an already imported project: `illuminator.py restructure PROJECT ORIGINAL.pdf` (backup `*.vor-restructure.md`; images of slots that only switch between chapter and section are kept). **Check the generated Markdown** (toolbar: "Open source"), especially for PDFs.
2. **Book**: the **Content** switch at the top (tabletop rulebook / other document, see "Content type"). Title, subtitle, kicker, tagline, running head, chapter label, colors, font size, justification. "Fill everything automatically" reads the beginning of the text and proposes all cover and running-head texts in the book's language (existing entries are replaced after confirmation).
3. **Style**: choose a preset (Anime Action, Film Noir, Dark Fantasy, Comic …) or write a free **style wish**, e.g. "should look like a 90s anime", and **refine**. The LLM turns it into a style suffix the selected image model understands and proposes matching accent colors. The suffix stays editable. **Compress** next to each field removes duplicates, contradictions, filler words and terms that have no effect on the chosen model. **Suggest** next to it lets the LLM propose the field (world/topic, style wish, style suffix, negative prompt) from the book, the other fields and the image model; existing text is replaced only after confirmation. The negative suggestion leaves out terms that contradict the chosen style (e.g. "pixelated", "lowres" for pixel art).
4. **Engine**: prompt generator (agy or Claude) and its model, and the **image engine** (agy, Gemini API or ComfyUI). With ComfyUI, "Connect" loads the models from the running ComfyUI; under **Image model** all models are listed with their detected architecture and the settings are applied on selection (see "ComfyUI models"). agy and Gemini need hardly any settings.
5. **① Plan prompts**: the LLM reads the text, describes world and genre, and writes a motif for every image slot. Without a style set, it also proposes style and colors.
6. **② Missing images**: generates all images that are still missing. With **Remove image** (below the prompt field; select several with Ctrl/Shift-click) you take out images you are not happy with: the file moves to `.build/removed/`, the prompt stays, the slot gets a new seed (otherwise the same image would come back) and "Missing images" produces it again. The dialog also offers "Remove and regenerate".
7. **③ Build PDF**.

**▶ All** runs 1–3 in sequence and skips what already exists.

### Refining single images

Select an image in the list. On the right you find the motif prompt, a separate negative prompt for this image (empty = default from "Style"), seed and "append style suffix". Thumbnails in the list update as soon as an image is done, not only at the end of the run.

- **New prompt**: new motif, optionally with a wish ("more night, two fighters").
- **Analyse**: the LLM looks at the current image, briefly says what fits and what does not, and improves motif and negative prompt (e.g. "fused fingers" if hands merged). A wish in the field above is taken into account.
- **Check**: image check only (✓ / ✗).
- **Preview**: renders with the current settings without replacing the image.
- **Apply**: replaces the image with the preview.
- **Generate & save**: regenerate directly.

An image does not fit? Enter a wish → Analyse → Preview → Apply.

### Filler images for empty space

Short sections often leave a gap at the bottom of a page because the next block (heading plus image) no longer fits. With **Book → Fill empty space with filler images** the tool first typesets the PDF as a trial, measures each gap from the configured height (default 55 mm) and creates an image slot `fill-…` for it. This only applies to gaps after a section that ends on that page. The LLM writes a second, different motif for the same section, the image engine produces it in the aspect ratio of the gap, and the build fills exactly that spot. The rest of the page layout stays the same.

If the text changes, the gaps move: fillers without a gap are simply not used, new gaps get their own image on the next "Plan prompts" / "Missing images".

### Image check (optional)

**Engine → Check generated images automatically**: after each generated image the LLM looks at it and judges motif, text artifacts, anatomy and whether it fits the world. With **Fix unsuitable images**, a failed image is corrected: with ComfyUI the LLM writes a better prompt and the image is regenerated with a new seed; with agy and Gemini the same image is edited instead (see "Image engines"). "Check images" checks all existing images, "Check" on a single image only that one. The result is shown at the image (✓ / ✗ with the problems found).

The following applies to the ComfyUI engine: **Retries** sets how often an unsuitable image is regenerated with an improved, similar prompt (up to 3). The switch **After 3 failures rewrite the concept radically (up to 3×3 images)** extends this: up to 3 images per concept; if none fits, the LLM rewrites the prompt from scratch. It knows the failed concepts and their problems and has to choose a different main motif, place and perspective that still fit the section. At most 3 concepts with 3 images each, i.e. 9 images per slot; it stops as soon as one fits. The result of the last attempt stays as the image even if none fit.

The LLM receives images only as a file (headless mode takes text only). The tool therefore creates a folder `.build/qc/<slot>/` per image containing only a downscaled copy. With agy it is started there with `--sandbox` and **without** `--dangerously-skip-permissions`, so it cannot run or write anything without an approval. agy can read the copy because the folder lies in one of its trusted workspaces:

```json
// ~/.gemini/antigravity-cli/settings.json
"trustedWorkspaces": [ "/home/<you>", ... ]
```

Claude uses only its read tool, pre-approved for that purpose.

Image size and portrait/landscape are not judged; the tool sets them (cover and background are portrait on purpose). The selected style (e.g. pixel art) is known to the LLM during image check, "Analyse" and prompt creation and is not treated as a defect.

If your project is outside all `trustedWorkspaces`, the image check with agy reports "agy could not open the image". Add the project folder (or a parent) there. Do **not** allow everything.

## Content type: tabletop rulebook or other document

The **Content** switch in the "Book" tab (asked when creating a project; on the command line `new … --type document`) controls how the LLM thinks:

| | Tabletop rulebook (default) | Other document (readme, tutorial, docs …) |
| --- | --- | --- |
| Motifs | Scenes from the game world, characters in action | Scenes, objects or visual metaphors from the topic; no fantasy/sci-fi extras, no screenshots, no code, no captions |
| "World" field | Genre, setting, era, tone | becomes "Topic": field, audience, tone |
| Cover | Iconic figures in combat | one clear emblem of the topic |
| Image check and "Analyse" | watches for wrong era or genre, monsters without reason | watches for fantasy intruders, wrong subject area and generic stock imagery |
| Style presets | Anime Action, Film Noir, Dark Fantasy … | Technical illustration, flat vector, isometric, blueprint, watercolor, editorial photo, minimalist, pixel art |
| PDF/text import | wording of the rulebook is preserved | additionally code, commands and paths stay in backticks and code blocks |

Switching only affects new LLM requests. Existing prompts stay; to replace them run "Plan prompts" with "overwrite existing". The layout itself is the same for both types.

## Images inside the document

Images in the Markdown (`![Caption](path/image.svg)`) are placed in the PDF where they are. Relative paths are relative to the Markdown file. Alt text becomes the caption, portrait images stay in the column, landscape images span both columns. SVG, PNG, JPG, GIF and WebP are supported.

When importing other documents their images are kept: Word images end up in `media/` and stay in place in the Markdown. For PDFs, larger images (from 200 px) are extracted page by page and inserted at the end of their page. Decorative elements may come along, so check `media/` and the Markdown briefly.

## Image engines

`project.json` → `"engine"` (GUI: Engine → Image engine):

- **`agy`** (default): agy (Antigravity CLI) generates the images with its built-in image tool using your own login, **no API key needed**. About 40–100 s per image. agy stores the images under `~/.gemini/antigravity-cli/brain/<conversation_id>/`, the tool picks them up from there. The conversation ID is stored as `interaction_id` in `images.json`; edits go through `agy --conversation ID`.
- **`gemini`**: direct call of the Interactions API (`gemini-3.1-flash-lite-image`), needs `GEMINI_API_KEY` or `~/gemini.key` and `pip install google-genai`.
- **`comfy`**: ComfyUI as before.

For `agy` and `gemini`:
- Only the aspect ratios 1:1, 16:9, 9:16, 4:3, 3:4 exist; the tool picks the nearest one and center-crops to the target size (wide banners lose some height). No seed and no negative prompt (negatives are appended as "Do not include …").
- `illuminator.py edit PROJECT KEY "instruction"` changes an existing image instead of regenerating it.
- Image check: 1 generation + at most 2 edits of the same image (only the problems found), then no further changes. The concept/regenerate loop applies to ComfyUI only.
- If agy's image quota is exhausted (`QUOTA_EXHAUSTED` in `~/.gemini/antigravity-cli/cli.log`), the run stops immediately with the reset time instead of waiting for images; a still-active quota error is also detected before the run starts. Switch the engine in the meantime.

## Prompt generator: agy or Claude

Under **Engine → Prompt generator** (or `project.json` → `"llm": "agy"` / `"claude"`) you choose which CLI writes the prompts and judges the images (image check, "Analyse"). For `claude` the model from `"claude": {"model": "sonnet"}` is used (`sonnet`, `opus`, `haiku`).

- Claude runs without tools in an empty temp folder (`claude -p … --tools "" --json-schema …`), no permission bypass.
- Only for judging images Claude may use the read tool to open the downscaled copy.
- The image engine is independent: with `engine: agy`, agy still generates the images even if Claude writes the prompts.
- Cost: calls go through your Claude account or subscription.

## ComfyUI models

Under **Engine → Image model** the tool lists all models from ComfyUI and detects their architecture from the file header (tensor names, not the file name). Selecting one sets workflow, text encoder, VAE, steps, CFG, sampler and scheduler. Changes you make afterwards under "Fine tuning" are remembered per model file (`~/.config/illuminator/models.json`, valid for all projects). **Recommended values** resets to the defaults.

| Architecture | Workflow | Defaults | Note |
|---|---|---|---|
| Krea 2 | Diffusion model | `qwen3vl_4b_fp8_scaled` (type `krea2`), `qwen_image_vae`, 8 steps, CFG 1, euler/simple | Turbo model, negative prompt has no effect at CFG 1 |
| Anima | Diffusion model | `qwen_3_06b_base`, `qwen_image_vae`, 28 steps, CFG 4, euler/simple | |
| SDXL / Illustrious / Pony | Checkpoint | 28 steps, CFG 6, dpmpp_2m/karras | Lightning/Turbo in the name: 8 steps, CFG 2, dpmpp_sde/karras |
| SD 1.5 | Checkpoint | 25 steps, CFG 7, dpmpp_2m/karras | |
| Flux (with encoder and VAE) | Checkpoint | 20 steps (fast: 4), CFG 1 | |

Not usable for text-to-image and greyed out: Flux Kontext (image editing), Wan (video), plain Flux diffusion models (only via "Custom workflow"), detection/pose models.

If a text encoder or VAE is missing, it is shown under the model with a download link. If a plain diffusion model only lies in `checkpoints/` (e.g. Krea 2 from Civitai), it appears with ⚠ and the button **Link into diffusion_models**. ComfyUI's diffusion-model loader only searches there.

**Krea 2 on cards with 16 GB or less:** the fast INT8 kernels need an RTX 3000 or newer. On older cards (e.g. RTX 2000 / Quadro RTX) ComfyUI takes a slower path that needs extra VRAM. Without reserve, generation aborts with "Allocation on device". Fix: start ComfyUI with `--reserve-vram 3` (with Pinokio in `comfy.git/start.js`). ComfyUI then offloads part of the model to RAM.

### Workflow types

| Workflow | For | Settings |
|---|---|---|
| Diffusion model | Anima and other models that load UNET, text encoder and VAE separately | Diffusion model, text encoder, encoder type, VAE |
| Checkpoint | SD 1.5, SDXL, Illustrious, Pony … (everything in one file) | Checkpoint |
| Custom workflow | anything that runs in ComfyUI (Flux, LoRAs, upscalers …) | JSON saved in ComfyUI via **Export (API)** |

With a custom workflow the tool fills in prompt, negative prompt, seed and image size automatically: it finds the KSampler, follows its `positive`/`negative` inputs to the text node and sets `width`/`height` in all nodes that have both.

## Command line

```bash
python3 illuminator.py new     PROJECT SOURCE    # create project (imports docx/pdf/txt)
python3 illuminator.py plan    PROJECT [--force] # write prompts (--force: all again)
python3 illuminator.py images  PROJECT [--all]   # missing images (--all: all again)
python3 illuminator.py edit    PROJECT KEY "instruction"  # edit an image (agy/gemini)
python3 illuminator.py check   PROJECT [--no-fix]  # check images (--no-fix: check only)
python3 illuminator.py restructure PROJECT ORIGINAL.pdf  # align heading levels with the original
python3 illuminator.py build   PROJECT           # typeset the PDF
python3 illuminator.py all     PROJECT           # plan + images + build
```

## Project folder

```
project/
├── project.json   settings (source, output, title, colors, style, engines)
├── images.json    per image slot: motif prompt, seed, style on/off, optional negative prompt, check result, interaction_id
├── images/        the generated images as JPEG (name = slot key)
├── media/         images from imported Word/PDF documents
└── .build/        intermediate files, previews, image check (do not version)
```

Slot keys are derived from the headings (`ch-…` chapters, `sec-…` sections, `fill-…` fillers). If a heading is renamed it gets a new slot and needs a new image; the old entry stays in `images.json`.

## Layout rules

- Short sections (under about 700 characters, no tables) get their image as a smaller image next to the text instead of a full-width banner.
- Tables with more than 3 columns, more than 8 rows or long cells are full width between the column blocks of the section (not as a column spanner, otherwise WeasyPrint pushes them completely to the next page and leaves empty space) and may break across pages; the header row repeats. Short tables stay in the column and in one piece.
- Generated images are never cropped: banners, side images and chapter images keep their aspect ratio (banners at most 66 mm high, then narrower and centered). The cover fills the page width; cover and background are generated in A4 ratio.
- Lines with `•` become lists, lists directly after a paragraph are recognized as lists, and short lines inside a paragraph (price lists, "Level 1 …") keep their line break.
- Emojis are set monochrome (Noto Emoji). Color emoji fonts crash WeasyPrint with HarfBuzz 14.

## What the Markdown should look like

- `#` book title (optional), `##` chapters, `###` sections. With several `#`, `#` are chapters and `##` are sections. This can also be fixed under "Book → Headings".
- A number at the start of a chapter ("3. Combat") is used as chapter number, a trailing parenthesis ("(The clash system)") as subtitle.
- Chapters whose titles start with "Anhang", "Appendix", "Änderungsprotokoll" or "Changelog" are set plain and single-column without a banner (patterns in `project.json` → `appendix_patterns`).

## Notes

- LLM calls run one after another. agy runs started in parallel interfere with each other and return empty answers. Missing prompts are requested once more.
- WeasyPrint paints `@page` background images only inside the page box; the page texture is therefore a fixed element repeated on every page.
- WeasyPrint cannot break a two-column block if it contains an indivisible element that fits in no column of the page; it then moves the whole section on. Figures in columns are therefore limited to 100 mm height. Place tall graphics in the middle of a section rather than at its start.
- Fonts (Bebas Neue, Oswald, Barlow, Noto Emoji) are downloaded by `fetch_fonts.py` into `rpdf/fonts/` (Google Fonts, SIL Open Font License); they are not part of the repo.
